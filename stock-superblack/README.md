# SUPERBLACK Workspace

แดชบอร์ดภาษาไทยสำหรับสต๊อกสินค้า ลงเวลาเข้า–ออกงาน และบันทึกการลา พัฒนาด้วย Next.js, React, TypeScript และ Bun

หน้าจอใช้ components ทางการจาก shadcn/ui รูปแบบ Base Nova ได้แก่ Sidebar, Sheet, Card, Table, Dialog, Field, Input, Native Select, Textarea, Tabs, Badge, Avatar, Empty, Alert และ Sonner ใช้ Tailwind utilities จัด layout และ responsive โดย `app/globals.css` มีเฉพาะ imports, theme tokens และ base layer ของ shadcn ไม่มี custom CSS สำหรับหน้าจอ

## เริ่มใช้งาน

รันจากโฟลเดอร์ที่มี `package.json` และ `bun.lock`:

```bash
cd stock-superblack
bun install --frozen-lockfile
bun run dev
```

เปิด http://localhost:3000 โดยใช้ username/password ที่กำหนดใน `.env` ผ่าน `AUTH_USERNAME` และ `AUTH_PASSWORD` ไฟล์นี้ถูกยกเว้นจาก Git และใช้เฉพาะฝั่งเซิร์ฟเวอร์ ให้สร้างไฟล์นี้เองเมื่อ clone ไปเครื่องใหม่

```bash
bun run lint
bun test
bun run build
bun run start
```

## การใช้งาน

- `/`: เพิ่มและแก้ไขสินค้า ค้นหาตามชื่อ/รหัส กรองหมวดหมู่/สถานะ และดูสินค้าที่เหลือไม่เกินจำนวนขั้นต่ำ
- ส่งออก Excel `.xlsx` ของสินค้าทั้งหมด โดยต้องระบุชื่อผู้ส่งออกทุกครั้ง รายงานมีชื่อ วันเวลาส่งออก และข้อมูลสินค้าที่บันทึกจริง
- `/attendance`: เช็คอิน เช็คเอ้าท์ ดูประวัติและระยะเวลาทำงาน รวมถึงบันทึกลากิจ ลาป่วย ลาพักร้อน และลาอื่นๆ พร้อมวันที่และเหตุผล
- แสดงชื่อผู้ใช้งานจากบัญชีที่เข้าสู่ระบบ เวลาใช้เขต Asia/Bangkok
- รองรับจอมือถือด้วย sidebar แบบพับและตารางที่เลื่อนแนวนอนได้
- `/admin/login`: หน้าเข้าสู่ระบบเฉพาะผู้ดูแล ใช้บัญชี `AUTH_USERNAME` และ `AUTH_PASSWORD`
- `/admin`: หลังบ้านแยกจาก sidebar ของพื้นที่ทำงาน ผู้ดูแลระบบอนุมัติ/ไม่อนุมัติใบลา ดูประวัติการเปลี่ยนสต๊อก และจัดการทะเบียนพนักงาน

## ผู้ดูแลระบบและพนักงาน

บัญชีใน `AUTH_USERNAME` และ `AUTH_PASSWORD` เป็นผู้ดูแลระบบ เข้าหน้า `/admin/login` เพื่อเข้าสู่ระบบ แล้วเลือกแท็บ **พนักงาน** เพื่อเพิ่มชื่อ อีเมล แผนก และรหัสผ่านพนักงาน (อย่างน้อย 8 ตัวอักษร) พนักงานใช้บัญชีของตนเองในหน้าเข้าสู่ระบบเดิม รหัสผ่านพนักงานเก็บเป็น salted scrypt hash และไม่ถูกส่งกลับผ่าน API

จำนวนพนักงานนับจากทะเบียน แยกเปิดใช้งาน/ปิดใช้งานและไม่รวมแอดมิน การปิดบัญชีจะยกเลิกสิทธิ์เข้าถึงในคำขอถัดไป โดยเก็บประวัติเดิมไว้ พนักงานเห็นเฉพาะประวัติลงเวลาและใบลาของตนเอง ส่วนรายการสินค้ายังคงใช้ร่วมกัน

ใบลาใหม่มีสถานะ **รออนุมัติ** ผู้ดูแลระบบยืนยันอนุมัติหรือไม่อนุมัติ (ต้องระบุเหตุผลเมื่อไม่อนุมัติ) ระบบบันทึกผู้พิจารณาและเวลา และไม่ให้เปลี่ยนผลซ้ำ พนักงานเห็นผลในประวัติการลาเมื่อโหลดข้อมูลใหม่ ใบลาเดิมที่ยังไม่มีสถานะจะถือเป็นรออนุมัติ

ประวัติสต๊อกบันทึกอัตโนมัติพร้อมการบันทึกสินค้า ได้แก่ ผู้บันทึก เวลา รหัส/ชื่อสินค้า หน่วย และจำนวนก่อน–หลัง ทั้งการเพิ่มสินค้า เพิ่ม/ลดจำนวน และแก้ไขรายละเอียด โดยไม่สร้างประวัติย้อนหลังให้ข้อมูลเดิม การแก้ไขจากข้อมูลสินค้าที่ล้าสมัยจะถูกปฏิเสธเพื่อป้องกันเขียนทับจำนวนของผู้อื่น

## การเก็บข้อมูล

เริ่มต้นโดยไม่มีข้อมูลสินค้า ประวัติลงเวลา หรือวันลา ข้อมูลที่กรอกจะถูกบันทึกฝั่งเซิร์ฟเวอร์ลง `.data/database.json` และยังอยู่หลังรีเฟรชหรือรีสตาร์ตเซิร์ฟเวอร์ ไฟล์ข้อมูลถูกยกเว้นจาก Git ควรสำรองโฟลเดอร์ `.data` เมื่อต้องการเก็บข้อมูล

เวอร์ชันนี้เหมาะกับการรันในเครื่องหรือเซิร์ฟเวอร์เดียวที่มีดิสก์ถาวร หากนำไปใช้กับ serverless หรือหลาย instance ต้องเปลี่ยนส่วนเก็บข้อมูลเป็นฐานข้อมูลถาวร การลามีขั้นตอนอนุมัติแล้ว แต่ยังไม่คำนวณสิทธิลาคงเหลือ

ใช้ `WORKSPACE_DATA_DIR` เมื่อต้องการเปลี่ยนไดเรกทอรีเก็บข้อมูล เช่น แยกข้อมูลทดสอบออกจากข้อมูลจริง ชุดทดสอบ `bun test` ใช้ไดเรกทอรีชั่วคราวและไม่แก้ข้อมูลใน `.data`

## โครงสร้าง

```text
app/                       หน้าจอและ API routes
  api/auth/                เข้าสู่ระบบและออกจากระบบ
  api/admin/               API เฉพาะผู้ดูแลระบบ
  api/workspace/           อ่านและบันทึกข้อมูล
  api/inventory/export/    สร้างรายงาน Excel
  attendance/              หน้าลงเวลาและการลา
  admin/                   หน้าผู้ดูแลระบบ
components/admin/          ใบลา ประวัติสต๊อก และทะเบียนพนักงาน
components/dashboard/      โครงแดชบอร์ดและ dialog
components/inventory/      หน้าสต๊อกสินค้า
components/attendance/     หน้าลงเวลาและการลา
components/ui/             components ทางการจาก shadcn/ui
hooks/use-mobile.ts        ตรวจขนาดจอสำหรับ Sidebar
lib/server/                session และการเก็บข้อมูลบนเซิร์ฟเวอร์
lib/api-client.ts          ตัวเรียก API ฝั่ง client
lib/types.ts               ชนิดข้อมูลที่ใช้ร่วมกัน
```

## สุ่มตารางวันหยุดและกะเข้างาน

หน้า `/admin` แท็บ **สุ่มตารางงาน** มีสามโหมด: สุ่มเฉพาะวันหยุด, สุ่มเฉพาะกะเข้างาน และสุ่มทั้งสองอย่าง เลือกพนักงานที่เปิดใช้งานได้ 1–100 คน เลือกช่วงวันที่ไม่เกิน 31 วัน และกำหนดจำนวนวันหยุดต่อคนรวมตลอดช่วงวันที่เลือกได้ ตั้งชื่อและเวลาเข้า–ออกได้สูงสุด 8 กะ โดยกะต้องเริ่มและสิ้นสุดในวันเดียวกัน

กด **สุ่มและบันทึกตาราง** เพื่อสร้างตารางใหม่ในฐานข้อมูล ทุกตารางเก็บการตั้งค่า รายชื่อพนักงาน ผู้สร้าง และเวลาสร้างไว้ ย้อนดูตารางเดิมได้หลังรีเฟรช และกด **ใช้การตั้งค่านี้** เพื่อสร้างตารางใหม่จากการตั้งค่าเดิมโดยไม่เขียนทับประวัติ

ระบบกระจายวันหยุดและจำนวนผู้เข้ากะรายวัน ใช้เฉพาะพนักงานที่เลือก ไม่รวมบัญชีแอดมิน วันลาที่อนุมัติ ณ เวลาสุ่มจะแสดงเป็น “ลา” ไม่มีกะ และไม่นับรวมโควตาวันหยุด หากวันว่างไม่พอจะปฏิเสธการสุ่มโดยไม่บันทึกข้อมูล โหมดเฉพาะกะจัดกะทุกวันที่ไม่ลาและไม่สร้างวันหยุด ส่วนโหมดเฉพาะวันหยุดจะแสดงวันที่เหลือเป็น “ทำงาน · ยังไม่จัดกะ”

ตารางเป็นแผนในหน้าแอดมิน ยังไม่ส่งให้พนักงานหรือผูกกับการเช็คอิน และไม่เปลี่ยนย้อนหลังเมื่ออนุมัติใบลาใหม่ ชุดทดสอบครอบคลุมสิทธิ์ API ทั้งสามโหมด โควตาวันหยุด ใบลา ข้อมูลไม่ถูกต้อง และการเก็บประวัติ
